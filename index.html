Hardwarenahe Skalierungsmechanismen & Formeln

Während die Prefill-Phase rechengekapselt ist ($\text{Compute-Bound}$ via $\text{GEMM}$), unterliegt die sequentielle Token-Dekodierung primär der Speicherbandbreite ($\text{Memory-Bound}$). Pro Token müssen die aktiven Schichten aus dem $\text{HBM}$ geladen werden.

// Autoregressives Dekodierzeit-Modell:
tdecode ≈ (Paktiv × bprecision) / BWmemory
• bprecision: z.B. 2 Bytes (BF16) oder 1 Byte (FP8)
• BWmemory: Effektive Speicherbandbreite (z.B. H100: 3,35 TB/s)
// Multi-Node Interconnect Latenz (>500 Mrd. Parameter):
TLatenz = TCompute + THBM + TAll-to-All
• TAll-to-All: Synchronisations-Overhead via NVLink & InfiniBand
Erkenntnis: Bei Riesenmodellen wie MiMo-V2.6-Pro (1.02T) oder Kimi K3 (2.78T) deckeln die Cross-Node Netzwerkbarrieren die Ausgaberate auf ca. 36–46 tok/s.
